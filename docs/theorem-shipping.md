# 定理航线、港口与虚芯片

## 操作

- 第二大关右上角「⚓ 航线」打开当前岛的港口；画布上的码头和入港芯片也能点击。
- 港口可切换岛屿、查看入港芯片的前提和结论，或定位源定理。选择「查看航线全景」可同时查看本章主辅岛与航线。
- 每座已揭示的定理岛默认有一座港口，实际占用岛岸 **4 × 3 个建造格**。港口管理中可免费新增、迁移或拆除，至少保留一座。新增/迁移后点击岸边高亮位置安置，绿色可建、红色不可建；右键拖动或 WASD 平移，Esc 取消。
- 港口避开目标星盘、前提建筑、已有电路和其他港口。普通放置、连续铺线、粘贴和布局移动也避开港口占地；兼容已有版本 3 存档时选择空闲岸线，不覆盖旧电路。
- 每条航线可分别指定出港、入港的港口；默认结合距离与负载自动分流。迁移保留港口身份与航线绑定；拆除后相关绑定恢复自动分配。
- 选择源定理 A，建立通向当前岛 B 的航线。规划不收费，也不要求先证明 A；可以撤销规划。
- 在 B 岛放置来自 A 的芯片会自动出现搭建航线。完整证明实际使用的依赖会保存为正式航线，移除后续电路也不会抹去已完成证明的历史。

## 状态

| 航线 | 含义 |
| --- | --- |
| 灰色虚线 | 手动规划，尚未用于电路 |
| 青色 | 电路搭建中的调用 |
| 紫色虚线 | 源定理尚未证明 |
| 金色 | 已完成证明实际使用的定理 |

箭头始终从源定理指向调用它的目标岛。标准画质有沿航线移动的标记；低画质或减少动态效果时保留静态方向箭头。码头显示入港定理名称、目标和公式，缩小时保留首个芯片以及其余数量，完整列表在港口窗口中展示。

岛屿总览、目标星盘、目标侧栏、最近定理与入港卡片默认显示完整的「前提组 → 结论」图形串。每条前提和结论单独调用现有命题图形渲染器，金色汇聚线表示定理推导，不把前提合并成公式内部的蕴含。三条以上前提排成两列，没有前提时明确标注「无前提」。点击岛屿图形或入港卡片可查看完整前提与结论文本。

详细视图中每港最多显示两张入港卡片，总览每港显示一张并标注剩余数量；多港口的卡片沿岸避让，以细线连回对应港口。绘制与点击使用同一套卡片布局。

## 虚芯片规则

第二大关第六章起，港口允许购买已发现但尚未证明的定理芯片。每次购买增加一次放置次数，价格为该定理普通放置费的两倍加 20 金币。粘贴或插入蓝图中的虚芯片同样消耗次数，多枚不足时整批取消。

虚芯片以半透明紫色虚线呈现，沿用普通定理的变量和前提端口。求解器仍检查完整公式推导，但只要实际输入依赖含未证明定理，该目标就处于待证状态，不发金币、芯片或通关奖励。循环依赖不会产生已证实的起点。

源定理独立完成后，库存中的虚芯片及已放置芯片自动转实；未用完的购买次数保留，再增加普通首次解锁的五次免费使用。仍保留完整电路的待证目标会自动重新检查并结算，不需要重新放置芯片。正式依赖记录只取实际流入匹配目标的信号来源，不把旁边未连接的芯片算入最终证明。

## 群岛与存档

主辅岛采用紧凑且跨章节稳定的布局，保留原有建造区域大小。地图视口查询同时考虑命名岛的新位置，避免岛屿移动后消失或与程序生成的背景岛重叠。

存档载荷版本为 3，使用 UTF-8 Base64；本地槽位、自动存档和导出的 `.logic` 文件采用同一种编码。中文批注与其他 Unicode 字符保留。两个导入入口接受 `.logic`、`.txt` 和 `.json` 文件，识别新编码及旧版第一大关 JSON。旧版第二大关地图存档不兼容，导入时给出明确提示。旧版第一大关重置快照也补齐新字段。

手动航线保存在 `metaProgress.plannedRoutes`，已完成证明的依赖保存在 `metaProgress.proofDependencies`；虚芯片状态和次数随定理库存保存。搭建航线从当前电路重建，避免另存一份容易失真的状态。

港口位置、朝向与编号保存在 `metaProgress.harbors`，航线两端绑定保存在 `metaProgress.routePorts`。仍使用版本 3；已有版本 3 存档缺少这些字段时补齐默认值。

## 验证范围

- `scripts/harbor-coast-verify.cjs`：两组种子十章共 148 座岛的默认岸线占地、增建/迁移/拆除、占地冲突、旧电路避让、绑定稳定性及存档往返；五档缩放的相邻港口卡片避让。
- `scripts/harbor-coast-browser.cjs`：真实画布增建、拒绝占用位置、迁移后绑定保留、拆除恢复自动分流、存档重载、390px 窄屏，以及实际四前提定理的图形与文字详情。截图位于 `artifacts/harbor-coast/`。

- `scripts/shipping-core-verify.cjs`：实际信号来源、断线、无关芯片、传递依赖、桥接器独立通道、待证/已证、循环、购买门槛和费用、复制扣次、Base64 与旧第一关兼容、十章稳定布局与相互不重叠。
- `scripts/shipping-browser-verify.cjs`：真实港口操作、手动建线、购买放置、画布点击、桌面与窄屏、导出/两个导入入口、存档内容。
- `scripts/shipping-resolution-verify.cjs`：预接普通 MP 电路及源证明测试夹具，浏览器补上源岛最后一段导线，验证实际完成回调依次转换虚芯片、结算目标与保存正式依赖。它验证状态生命周期，不替代玩家从公理发现完整源证明的测试。
- 既有美术回归脚本已更新为新载荷版本和 Base64 读取，保留旧第一关输入案例。

运行浏览器脚本需设置 `ART_PLAYWRIGHT`、`ART_BROWSER`，可通过 `ART_URL` 指定本地静态预览地址。检查截图及报告输出到忽略版本控制的 `artifacts/shipping/`。
