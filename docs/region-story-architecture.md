# 地域群岛与航行手记：实现及扩展约定

## 当前交付

新游戏使用地图版本 2：六个地域、十二个群岛簇、六十座稳定身份的岛屿。青庭内海、白岬环湾、琥珀浅滩、暮岩双峡、银霜高原、星晶远环分别采用草甸、白垩、砂岩、玄岩、霜原和晶簇风貌。它们目前都承载命题逻辑；地理不决定人物关系，也不代表已经接入新的数学分支。

地形仍是现有整数网格的真实建造表面。海湾、月牙、长脊、双叶、台地和破碎岸线由可控轮廓场生成。每座岛留出至少 100×80 格连续工作区，另保护前提与目标建筑。连通分量检查剔除孤立格子。港口继续占用真实岸线 4×3 格，沿用默认港口、多港口与航线绑定规则。

镜头可以缩到整张航图。低缩放时隐藏定理卡片、细港口名与主岛建筑标记，保留地形、地域名、探索航标和航线；放大后逐层恢复图形前提串、目标与电路网格。进入岛屿先取景整体轮廓，滚轮可继续放大，WASD／中键可平移，港口安置模式也支持右键拖动。

六处航标可通过航图定位，再在真实地图上点击调查、记入手记。这里只记录已调查状态，不引入角色行走、体力、旅行费用或强制剧情锁。数学岛屿仍遵循原章节开放规则，远处未开放内容保留地形轮廓。

剧情有十段主线、八段可选事件，合计 120 个正文段落、六组双选项，另有选项回答和后续回响；中英文对应。关系线采用用户确定的“慢热陪伴、有心动与约定”：建立共同手记 → 日常与互助 → 隐瞒引发分歧 → 坦诚裂痕 → 门前约定 → 真正完成证明后的尾声。

## 配置边界

| 层 | 入口 | 负责的事情 |
| --- | --- | --- |
| 数学内容域 | `src/data/world-regions.ts` / `MATH_CONTENT_DOMAINS` | 稳定域 ID、显示名、数据来源、符号配置 ID |
| 地域与风貌 | 同文件的 `WORLD_REGIONS`、`WORLD_BIOMES` | 空间骨架、色彩、地表纹样、可选岛形 |
| 群岛簇 | 同文件的 `WORLD_CLUSTERS` | 相对地域的中心、半径、方向、角度间隔、纵向比例、是否保留中心岛 |
| 岛屿地址 | `WORLD_ISLAND_ADDRESSES` | 稳定内容 ID → 地域、簇、簇内次序 |
| 地标 | `WORLD_POINTS_OF_INTEREST` | 独立探索 ID、位置、名称、描述与建筑类型 |
| 地形生成 | `src/lib/regional-world.ts` | 完整配置生成确定性位置、连通格子、边界缓存 |
| 数学关卡适配 | `src/data/stage2.ts` | 旧关卡配置提供公式、前提、奖励；版本 2 将其锚定到新地形 |
| 剧情数据 | `src/data/story.ts` | 场景、角色发言、选项、回响、表情、艺术场景 ID、触发条件 |
| 剧情状态规则 | `src/lib/story-engine.ts` | 条件判断、有效选项检查、跳过／完成状态与存档规范化 |
| 表现与阅读 | `StoryDialog.tsx`、`StoryJournal.tsx` | 打字、跳过、回看、重播、选择与手记；不参与证明判定 |

### 扩展地理

`createRegionalWorld(seed, contentWorld, definition)` 的第三个参数是 `RegionalWorldDefinition`，包含地域、风貌、簇、地址与地标。第二个参数是现有 `Stage2WorldConfig` 形状的内容提供者；不要求未来内容必须使用旧的坐标式 ID。当前 wrapper 传入旧关卡生成器，保留定理和奖励语义。

添加簇时提供 `WorldCluster`：`offset` 相对地域中心；`angle` 和 `step` 是弧度；`radius` 和 `radiusVariation` 是格数；`stretchY` 调整纵向比例；`centerIsland` 决定次序 0 是否落在簇中心。生成器不再依赖簇 ID 的命名后缀。全体岛屿的占用包络再做确定性分离，预留岸线与港口间距。

新增风貌可以使用已有六种纹样与六种岛形，数据中的配色会传入画布及航图。新的纹样／岛形属于渲染器或轮廓函数扩展，需要同时增加类型与测试；仅添加一个未知字符串不会自动生成新效果。

**已发布的地图版本必须冻结。** 位置计算必须接收该版本的完整地址目录，不能只传已发现或当前章岛屿。当前六十座岛屿从第一章就有固定地址，后续章节只补上内容。增删地址、调整簇、修改尺寸或轮廓算法，都可能重排地形；不能直接修改已发布版本来迁移存档。应新增地图版本并保留旧实现，或另做可审核的坐标迁移。此次版本 2 尚未对外发布，验收中可以统一调整。

### 未来数学分支

新增域时先登记稳定 ID、名称、来源与符号配置，再把地域的 `contentDomainId` 映射过去，并给内容提供者接入该域的定理与前提。地域名称和人物剧情不必随数学目录改变。当前 `symbolProfileId` 是适配标识，**不是任意 Metamath 公式已经可解析／求解的承诺**；真正接入新分支仍需相应解析、图形、类型规则与验证器适配。

示意配置应使用占位符，不预先指定后续分支：

```ts
const futureDomain = {
  id: 'future-domain-id',
  name: { zh: '待定内容域', en: 'Future content domain' },
  source: 'set.mm',
  symbolProfileId: 'future-symbol-adapter',
};
// 登记内容提供者与符号适配器后，再由某地域引用 futureDomain.id。
// 新版本的 definition 中添加地址和簇；不要改动版本 2 的已发布布局。
```

## 剧情与事件

`StoryScene` 用稳定 `id` 保存身份。`chapter` 和 `kind` 负责手记排序；`artId` 复用已有背景；每段可单独指定表情与光环状态。主线的 ID 延续 `stage2-1` 到 `stage2-10`，旧玩家的已读状态不会被清空。

`StoryCondition` 的条件采用“全部满足”：最低章节、已读／已跳过场景、已完成岛屿、农场开放／实际收获、同岛多港口、实际证明依赖、调查数量，以及可选内容域。未满足的可选事件不弹窗也不打断放置。手记按钮显示新的可读事件数，玩家主动打开阅读。

| 事件 | 条件与作用 |
| --- | --- |
| 尚未开花也可以来 | 第四章开场已读、农场开放；可不种植就相处 |
| 不太整齐的一篮 | 第五章开场已读、实际收获至少一次；日常有具体成果 |
| 不只有一条归路 | 第二章开场已读、至少一岛拥有两个港口 |
| 航线上的署名 | 第三章开场已读、已完成证明留下非空依赖；手动画航线不触发 |
| 路标的另一面 | 第一章开场已读、调查一处航标 |
| 同一片天空的不同岸 | 第三章开场已读、调查三处航标 |
| 把杯子递过来 | 第九章坦白后；继续普通相处，不把角色简化为谜题 |
| 下一页写我们 | 第十章开场已读、第二道门主岛真正完成；独立尾声 |

选项必须有稳定 `choice.id` 和 `option.id`。即时回答与后续 `echo` 都是双语文本；回响引用此前的选择 ID／选项 ID。没有隐藏好感数值、数学奖励、求解条件或必须刷取的关系门槛。新增剧情时把场景注册到 `STORY_SCENES`，配置条件与 `artId`，在主线入口或手记中开放。`isStoryAvailable`／`availableStories` 可以接受内容域参数，以供未来分支使用。

主线可以跳过，手记可以补读；补读完成会清除“已跳过”。重播会使用已有选择，可在当前回忆中试另一个回答，不写回真实故事。回看只显示当前已经读到的段落，记录玩家选择及对应回答。Enter／空格推进，Tab 在对话按钮间移动，Escape 返回对白或离开当前段落；对话期间按键不传给电路。

## 存档规则

外层存档仍是版本 3（既有 Base64 编码与 Unicode 处理保持），新增字段均在 `metaProgress`：

```ts
worldVersion: 1 | 2
discoveredLandmarkIds: string[]
story: {
  version: 1,
  skippedIds: string[],
  choices: Record<string, string>,
  reading: Record<string, number>,
}
```

没有 `worldVersion` 的已支持旧存档规范化为 1，继续使用原地形和原电路／港口坐标。新建游戏默认为 2。旧地图的航图窗口明确说明兼容策略；不存在默默把旧电路平移到新版地图的迁移。新旧地图共享新的剧情阅读器；旧的已读主线可在手记中重播完整新版文本。

缺失剧情字段补默认值；未知选择和值被过滤，阅读索引限制在场景范围内。主线完成、跳过、选项、阅读位置和地标发现进入普通存档。元进度变化后短暂防抖保存，离开页面时刷新当前画布与元进度；手动存档、自动存档、导出、重开章节快照统一规范化这些字段。

## 性能与验证边界

未知的未来地图版本或剧情版本会被拒绝载入，章节起始快照也会检查；不会将未来地图降级成旧地形。原始存档内容不会因为规范化失败而被改写。地图地标使用完整布局确定性避让建造区域，不会占用电路或港口格子。

地形用整数掩码和队列检查连通性，同步产出岸线边。画布沿岸线生成路径并缓存；细格子的 Path2D 只在放大到建造视图时创建，避免整图打开时生成数百万条细网格路径。缓存只服务显示，真实建造碰撞仍读取 `buildTiles`。

`scripts/region-story-core.cjs` 检查多个种子、所有章内容身份、跨章节地形稳定性、岛屿分离、连通工作区、前提目标和多岸线港口、新旧存档、事件条件、选项有效性及尾声条件。`scripts/region-story-browser.cjs` 检查实际画面、调查、选择、存档恢复、跳过补读、回忆、全部主线及窄屏英文。

`scripts/harbor-coast-browser.cjs` 支持 `ART_WORLD_VERSION=2` 检查新地图中的多港口、平移、迁移、绑定、存档与图形前提。`scripts/art-progression-verify.cjs` 同样支持版本 2；其证明是明确标注的预构造测试夹具，用于检验真实完成处理和奖励，不声称自动找到了玩家解法。

浏览器报告与真实运行截图在 `artifacts/region-story/`、`artifacts/harbor-coast-regional/`。完整验收结果记录在 `region-story-validation.md`。探索目前是二维地图调查与镜头导航，未来接入新数学分支、角色行走或其他剧情章节仍是后续工作。
