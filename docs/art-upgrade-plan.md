# 游戏美术全面升级计划

日期：2026-09-07 · 状态：用户已批准完整标准方案，实施与验收记录见 art-upgrade-implementation.md · 范围：现有第一、第二大关及公共界面

已确认方向：**延续现有女神形象，采用日系幻想、星图学宫与温暖空岛田园。**

这次升级的目标，是让玩家感到自己在修复一个由证明维系的世界：第一大关学习操纵精密的演绎器件，第二大关把这些器件带入群岛，在奥蕾莉娅的引导下修复定理、经营农场。人物、地图、器件和界面共享同一套视觉语言。

用户已批准 A–F 完整标准方案。本文件保留原始规划与验收目标；实际交付、检查结果与素材限制在 art-upgrade-implementation.md 记录。

## 2. 美术方向与统一规则

**世界风格：精密的数学结构，配合有生活温度的幻想环境。**

- 第一大关：深靛色工作面、象牙色刻字、旧金属边框、青蓝晶体、细密星图。场景细节集中在边缘，中央建造区保持安静。
- 第二大关：浮岛岩层、浅色石制遗迹、草地、云海、悬浮几何装置。进入建造尺度后，地表降低细节，让线路与端口清楚呈现。
- 剧情：日系绘画背景与现有角色统一光源、线条精细度和色温。奥蕾莉娅保留深蓝长发、蓝色眼睛、白蓝衣裙、金色几何饰件和晶体的识别特征。
- 农场：暖阳、浅木、麦金、低饱和草绿；蓝色灌溉光路、几何叶脉与发光莲花体现数学世界的身份。
- 共用母题：星盘、连通路径、定理铭牌、晶体、几何光环。装饰性符号与可操作的逻辑符号保持明确区别。

建议起始色板如下，最终在代表画面中校准对比度：

| 用途 | 建议色 | 使用规则 |
| --- | --- | --- |
| 主工作面 | 深靛 `#0B1425` | 电路和文字的稳定底色 |
| 正文与铭文 | 象牙 `#EEE8DB` | 正文追求清晰，装饰标题可更有书卷感 |
| 学宫材料 | 旧金 `#B69A66` | 降饱和、小面积使用，与黄色可证信号区分 |
| 公式信号 | 青蓝 `#59D6F0` | 贯穿线、端口、工具预览与图例 |
| 可证信号 | 金黄 `#F4CC67` | 贯穿线、端口与证明状态 |
| 田园环境 | 草绿 `#8FAE85`、暖土 `#A07854` | 用于场景和作物，不替代信号语义 |

原子 P/Q/R/S/T 延续既有颜色与形状映射，补足字母识别；统一工具栏、Canvas 元件和递归公式中的显示。界面标题可采用有书卷感的中文字形，正文采用清晰的中文无衬线，定理标签与数值采用稳定字宽。字体须覆盖中英文、希腊字母及 `⊢ ¬ → ∧ ∨ ↔`，并准备本地回退。

## 3. 各界面的具体改造

### 主菜单、存档与公共界面

标题画面采用“学宫窗前望向云海群岛”的构图：一侧保留清楚的开始、继续、读档和设置入口，另一侧展示星盘与远方浮岛。标志可从现有 `∴`、连线和星盘发展，游戏名称沿用现有命名。

统一按钮、提示、页签、资源计数、输入框、弹窗、工具提示、滚动条和聚焦状态。用一套规范的矢量图标替换风格不一致的 emoji；逻辑器件图标继续忠实表现实际元件。存档展示章节、日期和进度，具备数据时增加轻量场景/电路缩略图；旧存档使用对应章节插画回退。

### 第一大关：演绎工坊

| 对象 | 目标外观与反馈 |
| --- | --- |
| 原子 | 带字母与几何核心的晶体底座 |
| 逻辑门 | 保留轮廓识别，增加细刻线和材质层次，符号位于视觉中心 |
| 公理 I / II / III | 有清晰编号的封印板，端口排列一眼可读 |
| MP / MP+ | 精密推理装置，保留形状与文字差异，次数提示独立显示 |
| 定理芯片 | 学宫铭牌，展示真实 set.mm 标签、前提和结论；标准与简化版明确区分 |
| 显示器与目标 | 观测镜与目标星盘，求解成功后以短暂点亮反馈完成 |
| 导线与桥 | 暗衬底、语义色芯线、少量辉光；桥的跨越关系清晰 |
| 放置与编辑 | 幽灵预览、可放置轮廓、选中角标、非法位置提示与删除反馈 |

线、端口和公式属于最高可读性层级。错误用警示标记和局部轮廓表达，仍保留信号本身的身份。现有双向流动粒子只表达网络激活；输入输出与推理关系由真实端口和逻辑数据解释。

保留几何公式玩法，补充可查看的完整文本。长公式采用测量、换行、分层摘要与详情，不以持续缩小字体解决溢出；多前提芯片明确标示还有多少条前提。绘制效果依据真实节点尺寸、旋转与端口坐标，装饰外沿不改变建造占格。

### 第二大关：群岛世界与界面布局

沿用现有世界坐标与建造格，增加岩壁厚度、岛缘、草地、石板、云影和场景地标。建筑与植被放在不干扰建造的装饰区域。视觉地表准确提示可建造边界，云雾、藤蔓和装饰路径不会伪装成已连接线路。

深化已有的三档缩放表现：

| 视距 | 主要显示 | 淡出或隐藏 |
| --- | --- | --- |
| 群岛远景 | 岛屿轮廓、真实已揭示状态、章节地标、选中目标 | 器件细节、复杂公式、密集纹理 |
| 岛屿中景 | 定理名、主辅岛标识、目标摘要、建筑轮廓 | 细小环境颗粒、完整长公式 |
| 建造近景 | 地格、端口、线路、器件、目标与放置反馈 | 抢眼的云影和装饰细节 |

已锁定、已揭示、已完成、当前选中使用形状、标记、文字和适量色彩共同表达。远景连接线仅展示数据支持的关系。

桌面布局调整为顶部紧凑的章节与资源栏、可折叠的目标侧栏、底部器件匣、按需展开的定理与工作台抽屉。1366×768 的日常建造状态以约 65% 以上画面面积留给世界和电路为设计目标。教学提示跟随目标定位并避让，不再固定压住同一块 HUD；剧情、教学与章节介绍按顺序呈现。

### Galgame 演出：让奥蕾莉娅真正属于场景

角色素材改为透明立绘与独立场景组合，采用统一角色锚点、裁切安全区、光源与色温。常用姿态为“平静引导”和“施术/展示”，表情覆盖平静、微笑、思考、担忧、惊讶、坚定。根据现有台词配置，旁白或玩家发言时用适度光照变化区分主体。

对话框采用克制的星盘边角、独立姓名牌和舒适行宽，优先保证人物脸部与文字同时可见。增加逐字显示、点击补全文本、键盘继续和轻量淡入；减少动态效果模式直接呈现完整内容。这里涉及的新增交互限于阅读与演出。

### 农场：六块真正看得见的田地

采用轻度俯视的浮岛庭院，把六块田直接摆进场景。桌面常态同时可见六块田，选择种子后点击田块播种；选中田块在局部或侧栏展示名称、剩余时间、成本与收益。美术底图预留空白平台，田块、作物与可交互区域分层，确保画面中的田块与实际六块田一一对应。

| 作物 | 独特轮廓与细节 |
| --- | --- |
| 公理麦 | 金色麦穗、规律重复的节与叶脉 |
| 蕴含藤 | 朝同一方向生长的藤蔓、箭头感叶片、青蓝细光 |
| 矛盾莓 | 成对对照的果实、粉紫色莓果与有区别的叶片 |
| 定理莲 | 几何层叠花瓣、紫色发光花心、水面轻微倒影 |

每种作物设计四个生长视觉阶段，共 16 个作物状态；空田另有土壤状态。生长比例由现有 `plantedAt` 与 `readyAt` 计算，以 0–25%、25–60%、60–100%、成熟作为初始视觉分段，不增加计时或经济字段。

播种用短暂落土反馈，成长以轮廓变化为主，成熟显示明确标记，收获时果实/金币短暂飞向资源栏。减少动态效果模式使用静态成熟标记与即时数值更新。金币和灵感仍显示真实收益；视觉阶段沿用现有 1 / 5 / 20 / 60 分钟生长时长。

### 交易所、定理库与蓝图库

交易所呈现为铸造厂内的学宫工坊，展示 MP 引擎和芯片成品。价格、购买次数、剩余次数、资源不足与锁定原因保持醒目。

定理库呈现为学宫档案馆：列表适合快速查找，详情展示名称、完整前提、结论和真实来源。蓝图库提供基于实际节点的电路预览。物件插画用于帮助识别，公式与数值由程序绘制。

## 5. 工程落地方式

沿用项目现有 React / Next.js、Canvas 2D 与静态导出方式。建议把表现层组织为：

**现有游戏数据与求解结果 → 只读表现状态 → 共享主题、元件与素材定义 → 场景 / 电路 / 交互效果 → DOM 界面。**

| 工作包 | 主要落点 | 约束与目的 |
| --- | --- | --- |
| 共享主题 | `globals.css`、新建主题/素材定义模块 | 统一颜色、文字、间距、图标和层级；替换散落的覆盖式样式 |
| 电路表现 | `InfiniteCanvas.tsx`、`formula-renderer.ts`、`Toolbar.tsx` | 共享元件定义与预览；真实端口坐标作为唯一依据 |
| 场景表现 | `InfiniteCanvas.tsx` 的地图背景绘制、`Stage2Panel.tsx` | 复用已有轮廓缓存和细节分级，增加纹理与地标 |
| 剧情表现 | `StoryDialog.tsx`、剧情表现配置 | 按现有 sceneId 配背景、表情、姿态和光环，不改变主线事件 |
| 农场与交易所 | `LogicFarmModal.tsx`、`LogicExchangeModal.tsx` | 现有状态映射到场景；保留现有扣费、计时和奖励流程 |
| 系统界面 | `StartMenu.tsx`、`SettingsModal.tsx`、`TutorialOverlay.tsx`、`CircuitWorkbench.tsx`、`page.tsx` | 层级、布局、档案预览、低动态和画质设置 |

美术前置技术整理包括：

1. 将装饰动画时钟从逐帧 React state 更新中分离，尺寸调整只在窗口/容器尺寸变化时执行。目前 `flashPhase → drawNode → draw → resize effect` 的依赖链存在重复调整画布尺寸的风险，需要以运行分析验证并处理。
2. 增加 DPR 清晰度适配，并在低画质中限制渲染分辨率；绘制、鼠标坐标和命中测试使用一致变换。
3. 对节点与线路做视口裁剪，对重复器件外壳、地表与纹理做缓存；保留现有地图缓存，不重复建设。
4. 大幅静态背景不逐帧重画，辉光和粒子设预算；普通 / 低画质 / 减少动态效果覆盖 Canvas 和 DOM 两侧。[依据：MDN Canvas 优化建议](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)。
5. 素材按场景加载，剧情只预取相邻场景，田园与交易所资源按需解码；基础界面和操作入口可以先于大图就绪。

接线改造特别注意：求解器主要使用 `type: 'wire'` 的节点线段，不能遗漏这类真实线路。桥的上下跨线关系、四向旋转、锁定前提、普通/简化芯片差异、`⊢` 与公式的类型区分均纳入验收。

以现有关卡、数学语义、世界种子与布局、存档兼容、金币经济、农场计时和解锁顺序为实现约束。新增表现设置与存档解耦。表情、场景、作物状态优先从已有进度推导；必要的表现配置采用独立模块。

## 7. 验收标准

| 维度 | 必须看到的结果 |
| --- | --- |
| 风格 | 菜单、两大关、剧情、农场与交易所共享人物、材质、图标与排版语言；每种作物和重要地标有独立轮廓 |
| 电路语义 | 所有元件类型、四向旋转、放置/选中/错误/锁定/激活状态正确；端口与点击位置一致；关闭辉光仍可辨识 |
| 公式 | 中英文、长定理名、嵌套公式、多前提不溢出；完整公式可访问；真实 set.mm 标签与原文保持可查 |
| 关卡与存档 | 第一大关 10 关全部走查；第二大关 10 章及农场/MP 解锁节点、跨章节电路、旧存档与蓝图覆盖回归 |
| 剧情 | 十个地点匹配；立绘脸部、光环和文本无非预期遮挡；第 9 章裂痕出现时机与第 10 章表现符合现有事件 |
| 农场与交易所 | 6 块田、4 种作物、全部生长阶段正确；播种/收获/扣费/次数显示与数据一致，重新打开后视觉状态正确 |
| 尺寸 | 1920×1080、1366×768、1024×768，以及 390×844 的布局检查；中英文可切换；无重要按钮被裁切 |
| 缩放与高清屏 | 覆盖 0.1 / 0.2 / 0.4 / 1 / 2 / 5 倍缩放、DPR 1/2；细节切换稳定，端口不漂移 |
| 性能 | 同一机器、浏览器、固定场景对比前后帧耗时、输入延迟、内存和资源体积；常用桌面场景目标接近 60fps，大电路低画质目标不少于 30fps，待基线验证 |
| 构建 | 通过相关检查与静态构建；根路径和配置的子路径下资源无丢失，场景切换无控制台错误 |

普通文字对比度以至少 4.5:1、大字至少 3:1 为验收目标，透明面板按最不利实际背景检查。[依据：W3C WCAG 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

动态效果遵循系统的减少动态偏好，同时提供游戏内选项；关掉漂浮、粒子、视差后，成功、错误和成熟状态仍以静态方式可见。[依据：MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)。

窄屏目标是剧情、农场、菜单和基础操作布局可用；完整触屏电路编辑属于独立交互范围。压力场景先采用现有大电路，再补充固定的较大节点/线路样本；求解耗时与绘制耗时分别记录，避免将逻辑计算瓶颈误归为美术问题。
